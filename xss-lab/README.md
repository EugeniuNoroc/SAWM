# Лабораторная работа 3. Предотвращение XSS-атак (гостевая книга, Java)

Мини-приложение «гостевая книга» на Java (Spring Boot + H2): форма ввода и вывод
всех записей из таблицы `guest`. Показана XSS-уязвимость и защита от неё.

## Запуск

```bash
mvn spring-boot:run
```

Открыть: **http://localhost:8080/** (таблица — http://localhost:8080/h2-console, URL `jdbc:h2:mem:guest`).

На странице два режима (ссылки сверху): «Без защиты» и «Защищённый».

## Соответствие заданию

- Таблица `guest` (id, user, text_message, e_mail, data_time_message) — `DatabaseInitializer`.
- Гостевая книга (форма + вывод записей) — `GuestController`, `guestbook.html`.
- Демонстрация XSS (п.1) — режим «Без защиты».
- Проверки против XSS (п.2) — `XssValidator`, экранирование вывода, CSP, `validation.js`.

## 1. Демонстрация XSS (режим «Без защиты»)

Переключитесь на «Без защиты» и отправьте в поле «Сообщение» одну из строк:

Редирект на другой сайт:
```html
<script>window.location='https://example.com'</script>
```

Подмена всей страницы картинкой:
```html
<script>document.body.innerHTML='<img src="https://picsum.photos/900/600" style="width:100%">'</script>
```

Запись сохранится и при выводе выполнится как код — вместо текста произойдёт
редирект или вся страница заменится на картинку.

### Почему это работает

В режиме без защиты сообщение выводится как «сырой» HTML (в Thymeleaf — `th:utext`).
Браузер при разборе страницы встречает тег `<script>` и исполняет его. Данные
пользователя превратились в код страницы — это и есть XSS (stored XSS).

## 2. Защита (режим «Защищённый»)

**A. Экранирование вывода — главный приём.** Спецсимволы `< > " ' &`
заменяются на безопасные последовательности (`&lt;`, `&gt;` …). Тег становится
обычным текстом и не исполняется. В шаблоне это `th:text` (экранирует
автоматически), а в коде — `XssValidator.escape()`.

**B. Проверка ввода.** `XssValidator.validate()` отклоняет сообщения с тегами и
скриптами ещё до записи в базу (defense in depth).

**C. Заголовок CSP.** В защищённом режиме ставится
`Content-Security-Policy: default-src 'self'`, запрещающий сторонние/внедрённые скрипты.

**D. Клиентская проверка** (`validation.js`) — отсекает теги прямо в браузере.
Как и в случае SQL-инъекций, это лишь удобство: настоящая защита — на сервере.

## Проверка (тесты)

```bash
mvn test
```

`XssTest` печатает отчёт: payload без защиты сохраняется как есть; экранирование
превращает теги в текст; валидатор отклоняет все вредоносные строки; обычный
текст проходит.

## Главное отличие от SQL-инъекции

SQL-инъекция лечится параметризацией запроса (данные отделяются от SQL).
XSS лечится **экранированием при выводе** (данные обезвреживаются в момент
вставки в HTML). Общий принцип один: не смешивать данные пользователя с кодом.
